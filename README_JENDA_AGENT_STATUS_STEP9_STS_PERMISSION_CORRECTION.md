# Step 9 STS Permission Correction

## Correction

The JendaAgent direct upload flow uses Tencent Cloud `GetFederationToken` with
the backend CAM user's permanent key. This flow does not require a separate
CAM policy action such as `sts:GetFederationToken` or
`name/sts:GetFederationToken`.

Tencent COS documents that the GetFederationToken backup flow only requires
the permanent key to already hold the required COS permissions. The returned
temporary credentials are restricted by both the permanent key permissions and
the per-object policy generated by `StsDirectUploadTicketService`.

## Required CAM Policy

Attach this least-privilege COS policy to the backend CAM user whose SecretId
and SecretKey are configured in `AGENT_STORAGE_COS_SECRET_ID` and
`AGENT_STORAGE_COS_SECRET_KEY`:

```json
{
  "version": "2.0",
  "statement": [
    {
      "effect": "allow",
      "action": [
        "name/cos:PutObject",
        "name/cos:GetObject",
        "name/cos:HeadObject"
      ],
      "resource": [
        "qcs::cos:ap-shanghai:uid/1455545317:jenda-agent-1455545317/agent/*"
      ]
    }
  ]
}
```

Do not add a separate STS policy for GetFederationToken. Do not grant
DeleteObject, bucket listing, or full COS access for this demo flow.

## Verification

Start the backend with `AGENT_STORAGE_COS_STS_DURATION_SECONDS=1800`, open
`/direct-upload`, and upload an image. A successful response uses
`storageProvider: "cos-sts"` and returns a signed `imageUrl`.
